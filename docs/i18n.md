# Internationalization

BatchPlane uses English as the source locale and bundles Korean by default.

The UI should choose the best supported locale from the user's stored language
choice or browser locale. English remains the source of truth for keys,
terminology, and review order.

## Source Of Truth

- English resources under `apps/web/src/i18n/locales/en` define the required
  namespace and key shape.
- Korean resources under `apps/web/src/i18n/locales/ko` must contain the same
  keys.
- New locales must copy the English namespace structure exactly.
- User-facing screen copy, validation messages, GitHub API error messages, and
  Gate reason display messages should use i18n resources.
- Technical identifiers are not translated. Keep values such as `batchId`,
  `requestId`, `runId`, `reasonCode`, GitHub labels, workflow paths, YAML
  fields, action commands, and digest values as-is.

## Add A Language

1. Choose a BCP 47-style locale code that BatchPlane can detect from browser
   locale values, for example `ja`, `vi`, or `zh-CN`.
2. Add JSON resources under `apps/web/src/i18n/locales/{locale}`.
3. Copy every namespace file from `apps/web/src/i18n/locales/en`.
4. Translate values only. Do not rename keys.
5. Add imports for the new namespace files in
   `apps/web/src/i18n/resources.ts`.
6. Add the locale to `supportedLocales` in
   `apps/web/src/i18n/locales.ts`.
7. Add a display label to `localeLabels`.
8. Run the test suite.

Required namespace files:

```text
approvals.json
audit.json
batches.json
common.json
dashboard.json
errors.json
executionRequests.json
executions.json
failures.json
myWork.json
navigation.json
registration.json
schedules.json
settings.json
```

## Review Expectations

Translation pull requests should include:

- the new locale resource directory
- `resources.ts` registration
- `locales.ts` locale and label registration
- test output from `pnpm test`
- a short note for any intentionally untranslated technical terms

Reviewers should verify:

- English key names remain unchanged
- translated files have the same key set as English
- product terms stay consistent across screens
- validation and error messages are understandable without exposing raw adapter
  exceptions as primary copy
- Gate reason messages explain the control outcome while preserving the
  original `reasonCode`

## Tests

Run:

```bash
pnpm test
```

The translation completeness test compares each non-English namespace with the
English namespace. If a key is missing, extra, or placed under the wrong parent,
the test fails.

When adding or changing a screen, add at least a basic smoke assertion for
English and Korean rendering when the screen introduces new user-facing strings,
validation messages, or error messages.

## Common Mistakes

- Translating identifiers such as `REQUEST_DIGEST_MISMATCH` or
  `batchplane:execution-request`.
- Adding a key only to Korean because the immediate UI is being tested in
  Korean.
- Adding hardcoded fallback text in a component instead of a namespace resource.
- Showing a raw GitHub API message as the primary user-facing error.
- Showing only a Gate `reasonCode` without its localized explanation.
